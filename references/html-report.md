# 报告生成规范：课程包

报告是给用户拿去讲第一节课的，不是收藏的。判断标准只有一条：**他打开它，能不能照着念出第一节。**

## 一、交付形态

- 单页 HTML，A4 打印友好，正文宽度 900px，边距 43px；
- 用户环境支持时同时导出 PDF；页脚写「零基础做课 Skill」；
- 没有文件能力时，按下面四组结构输出纯文本，一组都不能少。

## 二、四组固定结构

| 组 | 回答的问题 | 包含小节 |
|---|---|---|
| 一、这节课是什么 | 讲给谁、讲什么 | 定位卡 / 学完能做到什么 |
| 二、这节课怎么讲 | 照着念的教案 | 时间轴 / 开场 / 三步 / 练习 / 收尾 |
| 三、幻灯片页纲 | 每页写什么 | 页纲表 |
| 四、今天怎么开始 | 现在做什么 | 开讲前待补 / 你的第一步 |

不新增「后续课程」「进阶推荐」「配套服务」这类模块。报告以「你的第一步」结束。

## 三、顶部区域

- 页眉左：`COURSE DESIGN`；右：`示例 · 视觉与结构模板`（正式报告写「20 分钟版」或「45 分钟版」）
- 主标题：两行，第二行是要点。如「把你会的一件事，<br>讲成别人的第一节课。」
- 副标题：`课程包 · 从「我会点什么」到「第一节课怎么讲」`
- 元信息行：左为学员摘要（谁在听 · 时长），右为生成依据（本次对话 · 未与学员验证）
- 摘要块：珊瑚色 kicker 写「这节课一句话」，一句加粗结论 + 两三句解释

## 四、摘要下方的三格决策条

固定三格：

| 格 | 内容 |
|---|---|
| 课名 | 用学员的问题当课名，不用方法名 |
| 谁在听 | 一种人 + 一个阶段 |
| 学完能做到 | 一个可验证的动作 |

## 五、视觉规格

沿用固定视觉系统，不要自创配色：

- 背景 `#edf1f2`，纸张 `#fbfcfc`，正文 `#27343b`
- 主色深蓝灰 `#31434d`，强调珊瑚 `#dc735f`，辅助雾蓝 `#edf3f6`
- 分组标题：`一、` + 中文词组 + 右侧灰色小注，下方一条 1px 分隔线
- 小节头：编号 + 标题，编号用细体数字，不用色块
- 强调只用一处：珊瑚色只用于 kicker、结论、标签、第一步横条

## 六、各小节写法

**01 定位卡**：五行表，`课名 / 谁在听 / 他现在的麻烦 / 学完能做到 / 这节课不解决`。每行一句，不要写成一页分析。

**02 时间轴**：一条横向分段时间条（开场 / 破错 / 三步 / 练习 / 收尾 / 作业），标注分钟。手机端竖排。

**03 开场第一句**：单独一个引用块，放原话，带引号。这是全报告最该被看到的部分，字要大一号。

**04 三步做法**：三张并列卡，每张四行：这一步干什么 / 怎么做 / 怎么判断做对了 / 常见错。不要写成段落。

**05 练习与收尾**：左侧练习场景与口令，右侧收尾三件事（复述三步 / 亮卡片 / 说边界）。

**06 幻灯片页纲**：表格，列固定为 `页 | 标题 | 这一页放什么`。10–12 行，不要合并成「6–10 页：三步讲解」。

**07 开讲前待补**：列出没答上的问题，每条写「缺什么 + 怎么补 + 大概多久」。这是最容易被跳过、也最有用的一节。

**你的第一步**：一个动作，一句话。比如「今天就录开场那 90 秒，不用往后录。」

## 七、内容纪律

- 只写用户提供或确认的事实。用户没说过的案例、数据、学员反馈，一律不写；
- 用户的口头说法保留原词（「小孩」「发火」「炸了」），不要换成「新人」「情绪激动」「负面反馈」；
- 不确定的地方写「待补」，不写「预计」「大概能」；
- 全文不出现价格、销量、收入、招生承诺；
- 示例模板里的所有内容都是虚构的，报告中必须换成真实内容。

## 八、交付前的检查

- 打开报告，从上往下读，能否在 1 分钟内看懂「讲给谁、第一句说什么」；
- 教案里每一句是否都能直接念出来，有没有「要讲清楚 XX」这种空话；
- 页纲是否 12 页以内；
- 学员带走的东西是否单独拿出来也能用；
- 导出 PDF 后确认分页没有把表格和小节标题拆开；窄屏下表格横向滚动而非溢出。
