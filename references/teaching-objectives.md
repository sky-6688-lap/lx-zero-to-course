# 进阶：设定这门课的目标

> **做第一节时不需要读这份文件。** 一节课的目标在 beginner-path.md 的第 1 问里就定了（帮谁、解决什么）。这份文件是「用户要做整门课」时才用的，用来把一节扩成一门。

教学目标是课程的北极星。它只有一句话，但决定了后面所有章节该留什么、删什么。

## 一、目标必须回答三个问题

1. 课程面向什么样的学员？
2. 解决学员哪些具体的业务问题？
3. 需要交付到什么程度的学习成果？

三个问题里有任何一个答不上来，课程就会变成讲师自述。

## 二、四类学员

| 类型 | 状态 | 课程该给什么 | 常见错误 |
|---|---|---|---|
| 没概念 | 完全没接触过这个领域 | 建立框架、消除恐惧、给最小可用动作 | 一上手就讲细节，学员崩掉 |
| 有了解 | 知道概念，没实操过 | 讲清判断标准与操作步骤 | 反复讲概念，学员觉得浪费时间 |
| 有经验 | 做过，但做法不成体系 | 帮他归纳自己已经在做的事 | 从零讲起，学员觉得被冒犯 |
| 资深 | 做得不错，缺突破 | 讲清方法背后的逻辑与适配边界 | 讲基础操作，学员直接退款 |

一门课只服务一类学员。同时服务「有了解」和「资深」，必然两头不讨好。

## 三、四种交付成果

不要用布鲁姆的六层原话，用这四层就够：

| 层级 | 学完能做什么 | 怎么验证 |
|---|---|---|
| 基本知道 | 说得出是什么、为什么重要 | 提问、小测 |
| 深刻理解 | 能判断某种情况该用哪一招 | 案例分析、判断题 |
| 简单应用 | 照着模板能做出一个结果 | 交付实操产出 |
| 熟练掌握 | 换一个场景也能自己调整 | 变形任务、复杂实操 |

**层级决定课程类型**：只到「知道、理解」可以是知识小课；要做到「熟练」基本只能是体系课程，因为需要练习和反馈。

## 四、一句话目标公式

```
让【哪类学员】，在【什么场景】下，能把【什么问题】解决到【什么程度】。
```

例子：

> 让刚接手内容排期的运营，在多人协作、临时插单的情况下，能独立排出一周的内容计划并完成一次复盘（简单应用）。

写完后做三个检查：

- 换成别的课，这句话还成立吗？成立 → 太泛，重写。
- 学员能自己判断「我该不该学」吗？不能 → 学员描述太模糊。
- 讲师能判断「这节该不该讲」吗？不能 → 成果层级没定。

## 五、必须做一次的定位偏差检查

真实案例：一位讲师发现「写邮件提需求」的模板特别好用，想做一门课叫《如何通过写邮件让产品经理理解需求》。

- **问题**：课程站在产品经理的立场，居高临下地要求业务方遵从流程。给谁讲、解决什么细分问题、交付什么成果都没定。
- **修正**：把学员换成业务部门同事，主题改成《如何提出产品经理无法拒绝的需求》。重点变成讲清产品经理怎么理解需求，再给一个邮件模板，让业务方把问题说得更准。

同一个方法，换一个站位，课程就从「我教你规矩」变成「我帮你把事办成」。

检查句式：

> 这门课是在讲「正确做法」，还是在讲「学员此刻的困难」？如果是前者，把主语从讲师换成学员，重写一遍目标。

## 六、按目标分配内容比重

目标定了之后，每个知识点都要回答「它对达成这个目标有几分必要」：

- **核心内容**：直接支撑目标达成的步骤和判断，占主要篇幅，必须配案例和练习。
- **基础概念**：目标学员已经知道的，一句带过，不要展开。
- **补充技巧**：有用但不影响主线的，放到附加说明或附录，不写进主干。

一门课里如果所有内容都同等重要，等于没有重点。学员记不住，也就学不会。

## 七、阶段成果模板

```
课程类型：知识小课 / 体系课程
目标学员：哪类人（工作年限、岗位、所处状态）
一句话目标：让【谁】在【什么场景】把【什么问题】解决到【什么程度】
交付成果层级：基本知道 / 深刻理解 / 简单应用 / 熟练掌握
这门课不解决：一句话（防止期待错位，也是后续答疑的边界）
```

「这门课不解决什么」这一句必须写。它保护学员，也保护讲师。
