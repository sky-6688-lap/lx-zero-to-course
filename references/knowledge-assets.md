# 阶段一：盘点知识资产

做课能不能成，八成取决于这一步找到的素材。讲师的常见错误是跳过盘点，直接从「我想讲什么」开始，结果写出来的课是自己想说的，不是学员要学的。

> **如果用户是第一次做课，先看 [beginner-path.md](beginner-path.md)，不要用这份文件。**
> 这份文件是「做整门课」时盘点素材用的，门槛较高（要负责过完整项目、要能报出数量）。做第一节只需要三个问题：谁问过你什么、你当时怎么做、他最容易错在哪。别拿这里的标准去筛一个还没做过课的人。

## 零、最低门槛的证据

做一节课不需要「标杆项目」，只需要两样：

1. **有人真的来问过他**——说明这个需求已经发生，不是他自己想的；
2. **他真的上手做过一次**——哪怕做得不漂亮，只要做完了、知道哪里容易翻车。

数量不必精确到个位。「这两年我们组来的人我都带过，大概七八个」比「说不清」有用得多，比编一个「带过 50 人」真实得多。**不要因为说不出数字就判定素材不足。**


## 一、三种值得做课的知识资产

按可交付程度从低到高排列，越往下越难做，但课程价值越高。

### 1. 重要项目

完成过一个完整的重要项目，特别是**以负责人身份全程参与**，说明你从实践中掌握了某个特定工作方法。

加分条件：项目具备标杆性质。比如策划出刷屏的营销案例、做出长销三年的课程、在头部公司负责过核心项目。标杆性决定了这个方法对陌生人有没有说服力。

### 2. 重复工作

多次做同一件事，而且**每次都有稳定产出**，说明你已经掌握了可依赖的工作能力，具备形成方法论的可能。

证据是数量，要具体：交付过 50 个项目、筛过 1000 份简历、面过 100 名应聘者、做过 300 个课时。说不出数量的重复，通常只是待过很久。

### 3. 判断决策

在某类工作或某个领域里，已经形成**下意识的判断**，看到情况就知道该怎么办，但往往说不清为什么。

这是最值钱也最难挖的一层。挖法是让用户回忆「你带新人时最常纠正他什么」——被纠正的地方，就是你已经自动化、对方还没有的判断。

## 二、怎么把经历倒出来

用户第一轮通常说得又少又笼统。按下面的顺序引导，一次只问一件事：

### 方法 A：时间线倒序

从最近往前走，3 年以外的经历大概率已经失去价值（工具、平台、玩法都变了）。问：

> 最近三年，你换过几家公司、做过几个岗位？从最近一段开始说，那段你主要负责什么事？

### 方法 B：能力模块法

先让用户说出自己的三五个能力模块，再在每个模块下填具体任务、典型项目、独特心得：

> 如果把你擅长的事分成三块，会是哪三块？我们先挑一块，说说里面你做过最具体的三件事。

### 方法 C：找现成材料

想不起来不是记性问题，是缺少线索。直接让用户翻材料：

> 把你最近的简历打开看一眼，上面写的项目里，哪个是你真正从头做到尾的？如果没有简历，述职报告或者 KPI 里的任务描述也可以。

### 五个辅助提问（用户卡住时逐条给，不要一次全抛）

1. 你曾在哪家公司、什么岗位，待了多久？
2. 你解决过什么问题，当时的情况是什么？
3. 你做过什么项目，最后拿到了什么结果？
4. 你重复做过哪些事？别人最常来问你什么？
5. 你做过哪些分享、培训，或者带过谁？

第 4 条最有价值：「别人最常问你什么」几乎等于「市场已经验证过的需求」。

## 三、把大任务拆成能做课的话题

一段经历太大，直接做成课会变成流水账。出现下列情况时，需要拆：

- 一个工作的步骤繁多且相对独立，其中有需要重点关注的问题；
- 一个工作从开始到完成超过半年；
- 一个工作涉及的角色很多，其中某些角色起了关键作用。

三个拆分维度：

| 维度 | 拆法 | 举例 |
|---|---|---|
| 按问题拆 | 不同团队、产品、工具带来的不同难点 | 「多团队协作下的需求评审」 |
| 按阶段拆 | 从早期搭建到成熟运营 | 「从 0 搭一套内容体系」 |
| 按角色拆 | 站在老板、产品、业务不同位置 | 「业务方如何向产品提需求」 |

拆分后的产物应该是**话题**，不是章节。话题的标准是：一句话能让目标学员认出「这就是我的问题」。

## 四、五维排序，选出先做哪一个

列出 5–8 个话题后，逐条打分（1–5 分），总分高的先做：

1. **时间近**：这件事发生得离现在越近越好，3 年内优先。
2. **成果大**：影响范围越大、结果越可量化越好。
3. **参与深**：全程负责优先于参与其中一段。
4. **可分享**：已经为他人讲过、写过、教过的优先，说明表达已验证。
5. **稀缺性**：有创新、市面上少见的优先。

不要只看得分，还要看一项否决条件：**这个话题你现在还愿意做吗？** 做过但极度厌恶的领域，做课会拖成灾难。

## 五、阶段成果模板

盘点结束后，按下面格式向用户确认（不要直接跳到设计）：

```
候选话题清单
1. 【话题】—— 资产类型：重要项目 / 重复工作 / 判断决策
   证据：做过什么、什么角色、什么结果
   排序：时间 5 / 成果 4 / 参与 5 / 可分享 3 / 稀缺 4
2. ……

当前建议先做：【话题】
理由：一句话（通常是证据最硬 + 需求最容易验证）
暂缓：【话题】，因为……
```

## 六、素材不足时怎么处理

这条只在**做整门课**时适用。做一节课时不要用它劝退用户——一节课的素材门槛只有「有人问过 + 他做过一次」，见本文开头的「零、最低门槛的证据」。

出现以下情况，不要硬撑出一门体系课程：

- 所有话题都只有「参与过」，没有「负责过」；
- 说不清任何结果；
- 重复次数少，且没有稳定产出；
- 没有第三个人用过他的方法。

处理方式不是让他回去等三个月，而是**把范围缩小到一节**：只讲他真正上手做过的那一次，讲那次的顺序、卡点和结果。等这一节有了学员反馈，再决定要不要扩成整门课。

只有一种情况真的建议先积累：他说不出任何一次自己动手做完的事，全部是「跟着别人做」。这时给一份积累清单：

> 现在还不适合做课。你缺的是「同一件事被反复做过并且结果稳定」这一段。建议接下来三个月，把 XX 这件事完整负责两次，每次记录步骤和结果；同时把你现在带新人的方式整理成文字。三个月后我们再回来做课，那时你能讲的内容会比现在厚一倍。
