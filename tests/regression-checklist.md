# 发布前回归清单

发布前逐条打勾。任何一条不通过，不发布。

## 一、流程

- [ ] 开场只说三件事（做什么、不用准备、大概多久），不超过 5 行
- [ ] 给了 A/B/C 三种状态让用户选，或直接问第 1 问
- [ ] 三个问题按顺序问，每问之间有一次复述确认
- [ ] 每轮只问一个主问题，问之前先回应用户刚说的内容
- [ ] 用户答不上来时往下给提示，不重复同一个问题
- [ ] 第 2 问收口后又补充的细节，按类别并进对应步骤，没有重走收口
- [ ] 用户说「讲过一节、效果不好」时走诊断，不重跑三问
- [ ] 整体 25 分钟内开始产出；没问完就先出半成品，标「待补」

## 二、判断质量

- [ ] 主题来自「谁问过你什么」，不是「你想讲什么」
- [ ] 三步不超过三步，每步是动词开头
- [ ] 至少一个「别人容易做错的地方」进了教案重点
- [ ] 没有因为「没数据、不资深」劝退用户
- [ ] 只有当用户主动要做整门课时，才谈课程类型和章节

## 三、产出完整度

- [ ] 四件齐全：定位卡、教案、页纲、学员带走的东西
- [ ] 教案有分段时间轴，20 分钟版各段加起来不超过 21 分钟
- [ ] 开场第一句是带引号的原话，能直接念
- [ ] 三步每步都写了「怎么判断做对了」
- [ ] 三步每步的「怎么做」里都有一句带引号的原话
- [ ] 有一处「什么时候这个方法不管用」
- [ ] 写了三个提问应答，其中包含「答不上来就说不知道」的说法
- [ ] 页纲 10–12 页，每页有标题 + 内容，每页不超过 3 行、每行不超过 15 字
- [ ] 学员带走的东西单独拿出来能照着用，并另给一份纯文本
- [ ] 第一步是一个动作，带时间

## 四、内容纪律

- [ ] 只使用用户本次提供或确认的事实
- [ ] 没有出现无来源的百分比、金额、学员数量
- [ ] 用户的口头说法保留原词（「小孩」「炸了」没被改成「新人」「情绪激动」）
- [ ] 不确定处标注「待补」，没写成结论
- [ ] 全文没有价格、销量、收入、招生承诺
- [ ] 对用户没使用术语（知识资产、交付物、方法论、布鲁姆、ABCD）

## 五、报告

- [ ] 四组结构完整：这节课是什么 / 怎么讲 / 页纲 / 今天怎么开始
- [ ] 三格决策条齐全（课名 / 谁在听 / 学完能做到）
- [ ] 开场第一句在报告里最显眼的位置
- [ ] 开场钩子里的细节（谁、哪句话、什么反应）全部来自用户原话，没有新增情节
- [ ] 教案组含「被问到时怎么答」三行，标题是学员的原话口气
- [ ] 「开讲前待补」列出未通过项，每条写清缺什么、怎么补、要多久
- [ ] 缺截图时给了「改前改后两栏文字」的替代方案，而不是只写「去截个图」
- [ ] 以「你的第一步」收尾
- [ ] 不含任何外部链接、二维码、报名入口
- [ ] 页眉、标题、页脚三处品牌名一致

## 六、边界

- [ ] 被问定价、发售、销售页时，说明了超出范围并给了替代动作
- [ ] 被要求代写整门课时，没有答应，但把第一节做完了
- [ ] 聊天交付消息只说三件事：做完了、这节课是什么、第一步做什么

## 七、技术

- [ ] `bash scripts/verify-release.sh` 通过
- [ ] 报告 HTML 在窄屏下表格横向滚动，时间轴与三步卡竖排，没有整页溢出
- [ ] 导出 PDF 后，小节标题与表格没有被分页拆开
- [ ] 报告中所有示例内容已替换为真实内容

## 八、时长一致性

- [ ] 页眉标注的时长与教案时间轴一致（10 / 20 / 45 / 60 分钟版），没有一律写 20 分钟
- [ ] 页纲行数与时长匹配：10 分钟 8 页、20 分钟 ≤12 页、45 分钟 14–16 页、60 分钟 16–18 页
- [ ] 45 / 60 分钟版的三步各 6–8 分钟且各带一个完整案例，没有靠拆步骤凑时长
- [ ] 10 分钟版页纲是 8 页，并且给了「下次讲 20 分钟加回什么」
